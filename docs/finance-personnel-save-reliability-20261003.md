# 人員新增與編輯可靠性：根因、驗收與交接（2026-10-03）

## 問題與修正

既有人員編輯時，畫面正式讀取欄位漏掉 `member_revision`，導致儲存 RPC 帶入預期版本 0，與資料庫目前版本不符而被拒絕。後端又把這種業務版本衝突以 PostgreSQL `40001` 回報；該碼代表可重試的資料庫序列化失敗，造成不必要的重試和漫長等待。人員資料並非必然遺失，應以正式讀回判斷。

本次前端正式名單讀取納入 `member_revision`，儲存時依讀到的版本做 CAS；衝突保持編輯內容、提示重新讀取，不自動覆蓋別人的修改。後端只把人員版本衝突改為非重試業務碼 `PT409`，真正的資料庫序列化失敗仍保留 `40001`。正式資料庫已套用來源鎖定的版本 `20261003042021`，postflight 通過；前台版本須另外以發布 manifest 與瀏覽器驗收確認。

## 同一次儲存的恢復

前台會在送出前保留 UUID、原始內容和原始預期版本。新 RPC 在同一交易內保存完成結果；同一位仍有權限的管理者，以相同 UUID 及內容重試只會回傳原結果，不會重複新增或重寫。相同 UUID 但內容不同會拒絕；原請求仍在處理會立即回覆待確認。只有欄位相同的讀回不能當作該操作的成功憑證。

正式回執版本 `20261003044426` 已套用，來源雜湊與權限 postflight 通過。原有 atomic RPC 保留相容；回執保證適用於新版前台的 reliable RPC，舊分頁需重新整理。

## 已完成的安全驗收

- `scripts/finance_personnel_save_live_canary.sql` 以唯一合成身分，在正式資料庫同一交易中呼叫真正的 `finance_admin_upsert_member_atomic_v1` 新增與編輯，檢查 Finance 人員、員工投影、Portal 使用者、部門角色、eDoc 來源 outbox 與管理稽核事件一致；再重播過期版本，預期 `PT409` 且所有投影保持不變。正式 canary 已通過並執行 `ROLLBACK`，回滾後合成身分不存在；未建立 Auth 帳號，也未修改真實人員。
- `scripts/finance_personnel_reliable_save_live_canary.sql` 在正式交易中測試新 wrapper 的新增、相同 UUID 重播只執行一次、不同內容拒絕、修改及舊版衝突，全部通過並回滾。沒有建立 Auth 或留下合成人員。
- 同 key 並發由資料庫 advisory lock 和唯一鍵防止雙寫；PGlite 同連線測試證明重播不重複寫入，未宣稱真雙連線競態驗收。
- eDoc 原始碼的每次受保護請求先檢查本地帳號狀態。合成身份單元驗證：本地已停用時拒絕既有 session 並標記撤銷，已失效的 resolver 結果拒絕；既有 eDoc 測試涵蓋人員／公司停用撤銷，以及 Finance v2 逾期重驗，4 個相關測試通過。正式站無 token `/api/auth/me` 回 401；這不能替代以真實停用 token 的端到端測試。

## 跨模組證據界線

正式 canary 證明 Finance 同一交易的來源投影與 eDoc **來源 outbox**，因交易回滾，不會證明 eDoc 另一個 Supabase 專案實際收到事件或新使用者已可登入。eDoc 收到停用事件後會將 user/link 設為 inactive 並撤銷 session；每次請求會檢查本地狀態，向 Finance 的 v2 重新驗證預設每 60 秒一次，可設在 30–300 秒內。事件送達前仍有最多一個重驗間隔的舊 session 窗口；Finance 不可用時受保護請求回 503，不放行。發布驗收需另外確認正式 outbox 送達、eDoc receipt、停用 session 的 401，不能把 Finance 來源檢查說成 eDoc 目標送達證明。

HR 私有 directory 橋接目前顯示 `pendingPeople=33`、`linkedPeople=0`，即使游標 revision 已 ack，也不能宣稱 33 人的 HR 任職連結或全模組就緒已完成。本次不改這批真實人員，也不把人員儲存可靠性修正擴張為 HR 歷史資料修復。

## 新人接替既有人員的操作

「編輯」只用於**同一位人**的姓名、信箱等資料更正；新人接任須用獨立人員 ID 新增，完成新人的 Google 身分綁定及必要權限後，從既有「離職交接」預覽待簽單、主管關係和接手人，再停用原人員。已完成單據的原簽核人保持不變。不可把離職員工的 ID、Email 或歷史簽核身分直接改成新人。Workspace 的舊 Google 帳號停用與新帳號啟用仍需依管理流程確認。

前台模擬傳輸驗收：20 項實際函式 VM 回歸；Chrome 與 WebKit 在 1440px／390px 共 117 項實際表單互動檢查。包含原 UUID 重試、跨關閉／重開復原、舊版本保護、明確失敗不誤報成功、切換身分丟棄舊回應與窄螢幕操作。這些使用虛構帳號與 mock RPC，不能視為真人 Google OAuth 或正式前台端到端證明。正式發布另以 workflow、commit manifest、前台資產雜湊及資料庫 postflight 核對。
