# 本人草稿獨立讀取

草稿原先在整批財務同步完成後才交付畫面，申請單、發票或繳費單逾時會拖住草稿。部分畫面直接以尚未確認的空陣列顯示 0 筆，容易讓使用者誤以為草稿遺失。

## 本次修正

- 本人草稿直接查詢獨立來源，不等待其他單據或分類帳。查詢保留原有 RLS，明示租戶、資料環境及本人 Finance ID；無 owner ID 的舊資料維持原有電子郵件規則。
- 同一身分共用讀取，整次讀取最多 12 秒；完整分頁與精確筆數核對通過才顯示確定筆數。錯誤有明確重試入口，不自動循環重送。
- 「我的草稿」及放款申請的草稿清單使用一致狀態：讀取中、讀取未完成、確認有資料、確認無資料。未確認不顯示 0 或「沒有暫存表單」。已取得的本人草稿可保留顯示，並標明清單尚未完整確認。
- 切換帳號、租戶、環境、權限或重新建立登入狀態會隔離舊回應。較晚完成的整批同步不再覆蓋草稿。
- 正式保存／刪除必須回傳匹配的草稿 ID 才更新清單；失敗保留表單或既有草稿。成功後取消較舊讀取，避免保存被覆蓋或刪除後復活。附件路徑及表單內容完整保留。
- 保存明示租戶，刪除明示租戶與資料環境。沒有放寬本人草稿寫入權限，沒有資料庫 migration。

## 驗證界線

`pnpm test:draft-readiness` 測實際讀取器及保存／刪除 handler，包括超時、空回應、完整分頁、身分變更、舊回應、附件、寫入確認等；已納入發布 preflight。`pnpm test:draft-readiness-browser` 使用實際 HTML／引擎和虛構唯讀來源，驗證 1440／390 px 清單、重試及繼續填寫。

本機測試不冒用真實員工，不修改正式草稿。正式資料只查匿名統計與 schema；正式發布另核對 protected workflow、release manifest 與所有靜態資源。這些證據不等同每位員工的真實 OAuth 操作或網路測速。
