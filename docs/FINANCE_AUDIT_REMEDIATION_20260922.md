# Finance 2026-09-22 稽核修正

此批以 `5f6820afe45d1c8d2563ab53d24bedf512ad5828` 為基準，修正全面稽核確認的 17 項缺陷，以及實作驗證時發現的兩項傳票問題。保留既有薪資資料隔離、正式金額、過帳記錄及各類表單簽核順序。

## 修正與驗收對照

| 缺陷 | 修正後行為 | 主要驗證 |
| --- | --- | --- |
| AUTH-01 同名越權 | 明確員工 ID 優先；衝突 ID 不因同名或流程文字而通過。無 ID 的舊記錄才使用受限身份映射。 | 真實 PostgreSQL helper／RLS：同名、不同 ID、歷史資料、停用及跨租戶正反例。 |
| AUTH-02 同職等越權 | 明確指派尊重員工 ID；未指定個人的職務佇列必須符合其授權範圍。 | 個人指派、共用職務、跨部門與跨公司正反例。 |
| AUTH-03 附件超出主單權限 | 已歸檔附件必須有可讀的來源單據；保留本人暫存及可驗證的歷史附件歸屬。薪資限制持續生效。 | 實際 metadata／Storage RLS、歷史批號、未知來源、薪資附件。 |
| ORG-01 任職資格錯用 | 主管候選使用該筆任職的簽核資格，不能借用其他部門的能力。 | 同人跨部門、任職到期、代理與可簽核旗標。 |
| T1 回應遺失造成重複發票 | 首次送出凍結內容、附件與操作識別碼。重按或刷新後核對原交易。 | 實際單張／批次發票／繳費單 caller；成功後斷線、刷新與再送。 |
| T2 舊送單回應污染新帳號 | 在等待前後核對身份、租戶、環境與登入版本；舊回應不更新新帳號快取或清除表單。 | A→B、A→B→A、撤權、租戶及環境切換。 |
| T3 未知收款被誤報失敗 | 原交易結果不明時，後续拒絕不能改判回滾或清除附件；提供核對原結果入口。 | 首次可能提交、後續 42501；附件清理與操作識別碼保持不變。 |
| T4 收款永久卡住 | 權限檢查、交易與讀回均有等待上限；釋放操作鎖並保留可恢復的原交易。 | 永不返回、延遲回應、重新載入恢復及同鍵重試。 |
| FE-01 應收搜尋需先離開欄位 | 輸入／中文組字結束後防抖篩選；保留原輸入框、焦點和游標，不逐字重讀伺服器。 | 桌機／手機實際輸入、組字事件及 RPC 次數。 |
| FE-02 選單鍵盤卡住 | 方向鍵保留目前選項；組字 Enter 不提前選值；Escape 還原原選值。 | 真實共用下拉選單，連續方向鍵與中文組字。 |
| FE-03 離開提示焦點穿透 | 原生 modal dialog 隔離背景，安全選項取得焦點，Tab 限制於對話框，Escape 留在本頁。 | 支出與收入未儲存提示、Tab／Shift+Tab／Escape。 |
| FE-04 排序只能點滑鼠 | 表頭提供鍵盤按鈕及排序狀態，重新排序後保留按鈕焦點。 | 桌機 Enter／Space 與 aria-sort；手機原卡片模式。 |
| FE-05 慢暫存覆蓋新導航 | 等待後再次確認導航及身份版本，較早的操作不得跳回旧目的頁。 | 慢保存、快速改頁、身份切換及保存失敗。 |
| E1 CSV 公式注入 | 匯出文字不能被當成公式；真正的數量及金額仍保留數值。 | 公式前綴、控制字元、負數與小數；LibreOffice 實際 CSV→XLSX。 |
| E2 CSV 引號毀損 | 共用 CSV 編碼器正確處理中文、逗號、雙引號及換行。 | Python 標準函式庫 strict CSV parser 往返比對。 |
| E3 匯出忽略篩選 | 傳票列表、統計與匯出共用公司、月份及關鍵字篩選；匯出涵蓋全部符合頁。 | 104 張跨頁資料與公司／月份／年度／文字／金額排除案例。 |
| E4 舊附件回應仍下載 | 簽章或 PDF 重建完成後重新檢查身份及父單權限；切換後不下載、不寫入舊操作提示。 | 切帳、A→B→A、租戶／環境／權限變動及延遲失敗。 |
| V1 月份写死 | 月份選單依實際資料建立，包含年份；9 月不會混入前一年同月。 | 桌機／手機動態選單、清單、統計與匯出一致。 |
| V2 傳票文字變成 HTML | 摘要、科目、建立者等按文字呈現；單號及 ID 安全傳入詳情操作。 | 實際瀏覽器惡意文字／帶引號 ID；清單與詳情無注入 DOM 或執行。 |

## 可重跑的檢查

- `node scripts/check_audit_export_integrity.cjs`：獨立 strict CSV parser、費用 CSV、全部符合的傳票資料與月份選項。
- `node scripts/check_attachment_download_names.cjs`：原始下載命名、正式簽章、拒絕回退舊連結，以及身份變更後的延遲回應。
- `node scripts/check_voucher_pagination_browser.cjs`：桌機 1440／手機 390，26 項清單、月份、跨頁搜尋與 HTML 安全驗證。
- `node scripts/check_finance_ui_interaction_browser.cjs`：原生 Playwright，70 項輸入、選單、對話框、排序及導航驗證。
- `pnpm release:preflight`：版本化來源、migration lineage、受保護發行、既有財務／簽核／收款／人資與本次新增回歸。

所有測試使用隔離資料或虛構使用者。資料庫測試使用 PostgreSQL 相容執行環境及實際 SQL；瀏覽器測試沒有代表每位員工實際通過 Google OAuth，也不代表正式環境所有請求小於 3 秒。

## 發行界線

本批新增資料庫 migration 及受保護發行階段；禁止只發前端後宣稱權限問題已在正式環境修復。GitHub 的提交、PR／CI 通過與正式部署是不同狀態。正式套用須按 `docs/FINANCE_PRODUCTION_RELEASE.md`，包含原子 migration／ledger、相容性檢查、唯讀 canary 及回滾演練。

無法追溯父單的歷史附件不能用放寬全員權限修補；本批不改寫正式金額、補造附件，或將尚未核對的應收差額視為零。
