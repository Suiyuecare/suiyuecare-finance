## 操作方式

- 薪資：在人資付款交接使用「薪資應計」，依核定資料填入各部門毛薪、代扣、淨薪應付及雇主負擔，附上來源證據；送審後由另一位具薪資讀取權的執行長／行政主管覆核。付款交接與應計分開勾稽，不能把淨付款當成毛薪。
- 憑證：在法遵與關帳的「憑證保存與驗證」，選法人與月份後「封存本期原件」，再「驗證封存原件」。只有索引的既有記錄不會被當成完成原件保存。
- 重要報表設定：先保存草稿，再由另一位授權人員覆核。覆核後修改會重新需要覆核。

## 證據界線

1. 合成 SQL／瀏覽器使用虛構身分，正式 canary 使用授權資料庫 claims 並回滾；這些不代表每位員工親自完成 Google OAuth 與所有操作。
2. 備份是目前使用者有權限的完整表格匯出與分頁件數檢查，並非資料庫一致時間點快照。正式災難還原需要隔離資料庫與 Storage 回復演練；此版本不提供直接覆寫正式帳冊的按鈕。
3. 原件 SHA-256 是登入用戶端實際下載及讀回副本的驗證，伺服器記錄該驗證事件並檢查範圍／物件大小／不可變性。不得宣稱伺服器另行獨立計算了物件內容雜湊。
4. 薪資功能不會用估算數字回補六月或七月。既有帳務需依核定來源及會計更正程序處理。
5. 本次桌機／手機受控回歸檢查不等於正式站全角色 p95 都已低於 3 秒；需持續保留實際逾時、冷啟動與網路樣本。

最終正式版 SHA、GitHub 工作流程結果與正式 manifest 證據以發布後驗收紀錄為準。

## 2026-09-28 正式發布演練修正

第一次正式演練偵測到新增功能放寬 `private` schema 使用權限，與既有人資目錄僅供後端服務使用的限制衝突。整個演練已回滾，沒有留下新資料表、migration 或權限變更，正式前台沒有切換。

修正保留既有人資限制：一般登入者與匿名者都不能取得 `private` schema 使用權限；薪資公開入口以固定空 search path 的受控函式，沿用原本的身分、法人、薪資讀取與獨立覆核檢查。驗收另加入 schema 權限拒絕、一般登入者正常封存／薪資操作，以及錯誤權限擴張會回滾的案例。
