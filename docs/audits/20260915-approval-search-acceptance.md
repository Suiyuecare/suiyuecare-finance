# 簽核紀錄搜尋改善與驗收

此文件區分本機功能驗證、正式資料庫診斷、真實 Google 登入操作及發布證明。任何一項通過都不能取代其他項目。

## 已確認的原始問題

2026-09-15 正式版本 `a31f70177be16f863365145429450357f3f143fd`，以執行長既有資料範圍執行一次唯讀「日照」診斷：資料庫約 5,795 ms、包含 JSON 序列化約 5,828 ms；回傳 97 組／全部 737 組；第一頁 50 組含 100 筆完整來源、231 個參與步驟、2,360,637 bytes。這是單次 DB 樣本，並非瀏覽器操作時間或百分位數，也不是 97 組正確性的獨立證明。

同日另以獨立測試瀏覽器中實際登入的執行長帳號，在正式站只執行搜尋，記錄「日照」最後輸入到 50 列結果完成兩次畫面更新為 **6,822.4 ms**，畫面顯示符合 97 組。這也是單次樣本，並非 p95。完整截圖及查詢時序保存在本機受限證據目錄，不放入公開原始碼或 CI 產物。

## 改善範圍

- 專用搜尋投影儲存正規化商務文字、金額與摘要；單據與部門修改在同一交易同步。
- 摘要清單不回傳完整附件、單據或簽核步驟，不將摘要放入完整單據快取。
- 開啟詳情重新確認身分及歷史參與範圍，再取完整批次。
- 非歷史分頁不啟動歷史全量搜尋；避免清單渲染重複掃描全域單據。
- 保留中文組字、取消舊請求、分頁、錯誤重試及登入切換隔離。

## 驗收條件

| 項目 | 門檻／證據 |
|---|---|
| 清單資料量 | 首頁 50 組未壓縮 JSON 不超過 200,000 bytes |
| 操作速度 | 最後輸入／中文選字完成到正確結果可點擊；指定一般辦公網路與裝置下每次 ≤3 秒、p95 ≤1.5 秒 |
| 正確性 | 「日照」「自費」、部門、姓名、單號、金額、多詞、無結果；以獨立宣告的應有單據 ID 比對所有分頁 |
| 完整性 | 總筆數一致，無漏筆或重複；完整批次只在詳情取回，金額不因分頁改變 |
| 權限 | 本人參與可查、未參與／外租戶／錯環境不可查；停用及登入更換立即拒絕 |
| 更新一致性 | 新增、修改、刪除、批次移動、部門更名、交易回滾後投影與來源一致 |
| 錯誤情境 | HTTP／DB 逾時可重試，不能當成功 0 筆；舊查詢和舊登入回應不能覆蓋新狀態 |
| 真實登入 | 員工、主管、會計、執行長代表帳號經 Google 登入；紀錄環境、版本、預期／實際 ID、延遲分布及操作影片 |

## 驗證工具與目前狀態

- `check_approval_history_summary.cjs`：隔離 PostgreSQL，虛構人物與單據，涵蓋索引、觸發器及授權。
- `check_approval_search_summary_browser.cjs`：實際 HTML → HTTP → PostgreSQL RPC → JSON → 畫面；獨立預期清單、737 組及大型附件、桌機／手機、分頁、延遲與失敗。其身分為隔離測試身分，不能當作 Google OAuth 或正式站效能證明。
- 保護式發布會驗證完整前置版次、回滾指紋、新舊資料庫契約及固定候選產物。
- 已取得執行長登入後的正式站操作基線；新版發布後仍需重測。其他員工、主管、會計真人帳號尚未完成登入驗收。

測試結果與發布資訊完成後填入下方；未執行的項目不得以推測補填。

## 正式演練暴露的長文字索引問題

第一個正式發布流程 `34935253855` 在資料庫回滾演練遭遇 HTTP 524；前台沒有切換。唯讀確認 migration 紀錄為 0，兩張新投影表與新搜尋 RPC 都不存在，演練已回滾。

原始測資涵蓋大型附件和 103 張批次，卻未涵蓋正式長中文內容的分布。正式唯讀統計為 2,203 筆來源／737 組，最大發票群組有 40,141 個商業文字字元，組合正規化與原文後的索引輸入超過 80k 字元。舊方法對每個位置重做 UTF-8 `substr`，原生 PostgreSQL 的 32k 字元已耗時約 6.1 秒，80k 與 128k 都觸發隔離測試的 30 秒逾時。

修正改成一次拆字後組合相鄰字元，保留完全相同的單字元／雙字元集合。SQL 測試增至 83 項，涵蓋 Unicode 集合比對及 128k／256k 長文字。瀏覽器測資新增每張 600 字的 103 張批次，要求索引輸入至少 120k 字元、回填 ≤30 秒、103 張整批更新 ≤3 秒；既有搜尋 p95／最大值門檻不變。原生演練另以與正式相同的來源／群組筆數核對。

修正後 migration SHA256：`e0b612473520fcb5a9b6319028d3ef9f02a4a68de3a80ca4fb1f8cbce0568403`。正式上線與使用者帳號結果仍須以後續發布及現場驗收確認。

補強後的原生 PostgreSQL＋HTTP＋瀏覽器 366 次驗收通過：最大索引輸入 148,519 字元，回填 1,079.7 ms、103 張整批更新 161.8 ms、搜尋 p95 347.5 ms／最慢 359.4 ms。另以正式相同的 2,203 筆／737 組虛構資料，將各批次灌到接近實際最長文字，精確新 migration＋新 postflight／canary＋完整 fingerprint 的單次原子演練耗時 7,856 ms，前後指紋一致且新物件完整回滾。這個本機演練不包含其他模組的 18 份舊契約，不能替代正式發布的完整演練。
