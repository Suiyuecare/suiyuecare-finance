## 已確認缺陷

### 1. 股東／公司間往來送件缺少必要識別碼（P1）

`index.html:31720` 建立的 `formPayload` 沒有 `submissionAttemptId`，`:31723` 透過正式送件 RPC 提交。正式資料庫 `finance_submit_expense_request(jsonb,uuid,text,jsonb)` 的目前函式定義仍包含識別碼檢查與「頁面版本已過期」錯誤。本次用原前端函式和合成後端 guard 重現 `result=false`、`hasSubmissionAttemptId=false`。

附件在 `:31716` 已上傳、通知在 `:31722` 先發送，失敗路徑只移除本地請求與通知，未清理上傳附件。合成重現得到上傳 1 個、清理 0 次、外部通知嘗試 1 次。Demo 跳過正式 RPC，不能用 Demo 成功判定此流程可用。

**驗收：** 正式授權身分的出資、借款、還款，有／無附件皆成功；回應遺失以同一識別碼重試只產生一張單；確定失敗不外發通知且清理暫存附件，未知提交結果須先讀回確認。

### 2. 傳票更正將小數金額取整數（P1）

`index.html:29402` 使用 `Math.round(num(e.amt)*ratio)`。合成原傳票 100、調整 10.50，產生借貸各 11；0.30 全額沖銷先被前端轉成空分錄，`:29420` 拒絕繼續。正式全額沖銷 RPC 本身可能保留精度，但此小額案例在呼叫 RPC 前已被阻擋。

**驗收：** 10.50 調整及 0.30 沖銷精確保留；多行分攤尾差只按分位處理，借貸總額相等且等於指定金額。

### 3. 關帳與報表的平衡判斷不一致，伺服器未重驗（P1）

`index.html:5783–5785` 的關帳檢查容許差額小於 0.5；`assets/engines/financial-statements.js:3,225–228` 的試算平衡容許值為 0.005。合成借方 100、貸方 99.90，前者通過、後者不通過。

`:29387–29396` 通過前端檢查後直接保存 `period_closes`。正式 catalog 確認該表沒有非內部 trigger，INSERT 政策只要求會計角色；目前約束是主鍵、法人月份唯一鍵和租戶外鍵，沒有重新檢查分類帳借貸平衡。因此不能依賴伺服器擋下前端誤判或查核後新增分錄的競態。

**驗收：** 0.01 差額阻擋關帳；報表與關帳採一致分位精度；伺服器同交易重新核對完整授權期間資料，與入帳作業協調鎖定；前端查核後新增分錄也不能造成錯誤關帳。

### 4. 備份還原欄位遺失，且成功訊息不等於正式恢復（P1）

備份保存前端欄位 `eid/by/time/docs/fileCount`，`:29325–29328` 還原卻用只接收資料庫欄位的 mapper（`:6280–6283`）。合成匯出再還原後，法人 `eid:F1` 變成未定義，關帳人、時間及封存件數等也可能遺失。這會影響前端關帳狀態，並不表示正式資料庫因此解鎖。

`:29335–29337` 記錄還原完成、顯示「還原完成」，實際只覆寫前端資料；正式遠端恢復要另做。備份產生 SHA-256，但讀入／還原沒有驗證雜湊，也未強制阻擋不同環境的備份。

**驗收：** 匯出還原完整 roundtrip；驗證雜湊與 schema／環境／租戶；正式模式不能把畫面替換登記為正式恢復完成；正式恢復須隔離驗證、可回滾並有完整稽核結果。

### 5. 特殊字元描述搜不到（P2）

`:26013–26019` 把畫面摘要 HTML 當搜尋文字，摘要已在 `:25703,25705,25718` escape。合成 `A&B 訂閱` 變成 `A&amp;B 訂閱`，搜尋 `A&B` 回傳 false。

**驗收：** 搜尋使用原始文字，畫面保持安全 escaping；`A&B`、引號與大小於符號查詢均正確。

### 6. 整批單據搜尋漏掉後續成員文字（P2）

`:26022–26029` 遍歷整批成員時只加金額，文字摘要主要取代表單據（`:25702,25709–25710`）。合成第二張獨有描述搜尋 false。

**驗收：** 整批每张已授權成員的單號、客戶、描述都可找到同一批次，結果無重複，金額不變；不得為了搜尋引入未授權兄弟單資料。

### 7. 跨頁批次勾選顯示數與執行數不同（P2）

`:25605,25610` 累計全部選取，`:25641–25643` 僅從目前 `apprItemMap` 取單。翻頁會重建當頁 map（`:26237,26263–26267`）。合成兩頁各勾一張，畫面計數 2，實際待執行只有 1。

**驗收：** 跨頁或搜尋後顯示數必須等於真正待執行 ID；若只支援當頁選取，要明確清除旧選取與更新數量，不能靜默漏單。

### 8. 組織草稿晚到的儲存回應覆蓋新編輯（P2）

`:38020–38022` 等待回應後無條件替換 snapshot、標 `dirty=false`；期間仍可操作主管／代理／停用（`:37978–37988`）。合成延遲回應：期間停用單位後 `active=false,dirty=true`；回應抵達變成 `active=true,dirty=false`，新修改消失。

**驗收：** 延遲 3 秒期間修改主管、代理、停用或換草稿，舊回應不得覆蓋新內容／其他草稿；未送出的修改保持未儲存狀態。也可明確鎖定儲存期間的編輯。

### 9. 身分連結與入口角色的跨租戶隔離政策不足（P1）

正式 catalog 確認：

- `finance_identity_links_manage_people_admin_20260610` 是 PERMISSIVE ALL，只檢查執行長／行政主管／人資角色，沒有 `tenant_id=current_tenant_id()`。另一個有租戶條件的 SELECT 政策會與此政策以 OR 組合，不能限縮它。
- `finance_portal_roles_select_authenticated` 是 PERMISSIVE SELECT，只檢查已登入，沒有租戶限制。
- 兩表 authenticated 有必要讀写權限、強制 RLS；非內部 trigger 只有更新時間，身份／角色外鍵為單欄，沒有複合租戶約束補足防護。

這是資料庫政策缺陷，涉及不同系統租戶。不能把同一租戶內經授權的跨公司管理當成異常，也沒有證據顯示今日已發生資料外洩。

**驗收：** 使用兩個合成租戶驗證一般員工及管理者均不能讀／改另一租戶的身分與角色；自租戶正常功能保留；跨租戶身份／角色關聯在資料庫拒絕。

## 功能尚未完善

1. **薪資應計與部門成本銜接。** 正式 `finance_hr_private.finance_hr_post_voucher` 仍只核對實付淨額，部門固定空白；毛薪、代扣及雇主負擔需另行會計處理。應以核定薪資與另作分錄勾稽，不以淨付款猜毛薪。本次未查正式薪資明細，不能據此斷言六月／七月實帳錯誤。驗收需確認薪資所屬月、各部門應計費用、代扣負債與淨付款對應。
2. **附件長期保存與還原演練。** `index.html:29354` 的封存功能明確只保存索引件數與目標日期，尚未複製、驗證或鎖定附件內容。應補原件雜湊、備份、保存到期管理與還原抽測；索引建立不代表原件已妥善保存。
3. **重要設定第二人覆核。** `docs/finance-reporting-contract.md:41` 明確允許同一管理者覆核自己編制的預算／分攤／沖銷工作底稿設定。可補編製人與覆核人分離、版本退回及覆核後修改重新核准。現有此類設定為管理工作底稿，並不等於正式總帳入帳。

## 尚不能直接判為 bug 的事項

- 搜尋既有金額 43 項、歷史輸入 34 項回歸通過，但沒有涵蓋上述特殊字元與整批後續成員案例。
- Supabase 健檢有權限政策重複、RLS 逐列計算及外鍵未建索引等效能警示。它們是优化線索，不能只憑警示斷言使用者某次逾時的原因。
- 現有讀取測試使用受控延遲服務；timeout 12／30 秒不是完成時間證明。需正式站分角色測量冷啟動、中文輸入、翻頁、詳情與報表，從操作到正確結果可使用為止，保留失敗與逾時樣本；關鍵操作的第 95 百分位目標可設 3 秒內。
- 組織／角色 catalog 的晚回應缺少明確身份代次比對，需跨分頁換帳號與恢復登入實測。現有 fetch 有身份保護，不能直接宣稱已越權。
