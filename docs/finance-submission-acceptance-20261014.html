案例驗收條件證據層級

部分寫入及重複最後一筆驗證失敗時全批回滾；相同識別重試回原結果；不同內容沿用識別必須拒絕；並行重試不能產生第二批。資料庫交易與並行測試。
真 HTTP 呼叫經固定版 PostgREST、簽章測試 JWT、權限判定及資料庫寫入，驗證公開 RPC 參數、結果回查與拒絕未授權呼叫；已撤銷或不存在的登入 session、停權與錯誤 Google 綁定必須拒絕。全部資料與憑證均為隔離測試用。真 HTTP + 隔離 PostgreSQL；不等同公司 Google 正式登入。
190 張瀏覽器保存失敗Chromium/WebKit 實際 localStorage、sessionStorage、IndexedDB；大筆資料保存、配額不足、單一儲存失效、重開頁面復原及結果未知情境；不得因保存一份重複大型 payload 而無法送件。真瀏覽器與真本機儲存；外部 HTTP 可由 fixture 模擬並明列。
Office 檔讀取兩份 DOCX 與 XLSX 事件規格、空 MIME、中文檔名、有效 OOXML、草稿轉正、發票附件共用直接上傳路徑；真 TUS 對 loopback 測重試、續傳、取消。有效檔案內容 + 傳輸 fixture；正式 Storage 權限另由正式只讀 canary 驗證。
既有簽核及人員規則採購第八關金額加憑據、會計最終金額、浮點尾差、合法會計／出納身分、組織版本競態、抽單、歷史完整性既有測試持續必跑。release:preflight 既有回歸與互動測試；角色測試不代表代登入真實員工帳號。
可追查性建置頁面含真實來源 SHA；送件識別、階段、結果、耗時、錯誤碼在允許欄位內保存，離線暫存不掉欄位。不得紀錄檔案內容、完整敏感表單或憑證。建置精確內容驗證 + 診斷離線佇列回歸。

發布順序

  1. PR 的 release-gate 與 interaction-gate 通過，包含原生批次、HTTP 及瀏覽器保存回歸。
  2. 合併後固定 protected-main 40 碼 SHA；從該 SHA 重新測試及封裝不可變產物。
  3. 執行 database_invoice_batch_bulk_20261014，只允許 20261014123427 及封存 SHA-256。先驗舊函式、權限與觸發器，再演練回滾並比對指紋，最後原子套用及後驗。
  4. 此資料庫階段不得改正式前台 alias。保留原 alias、manifest 的前後一致證據。
  5. 再執行同一來源 SHA 的 frontend_compat。未安裝新批次交易或函式指紋不符時，一律停止；正式推送前再次驗證。
  6. 檢查正式網域 manifest 的 source_commit、HTML／JS bytes、版本欄位及正式錯誤紀錄。只讀後驗不能作為真實成功送出 500 張的證據。

驗收紀錄

工作流程產生 finance-submission-acceptance-20261014/manifest.json，保留測試案例數、容量各次耗時、證據檔案雜湊與來源 SHA。瀏覽器與 migration 的證據必須符合當前原始碼；正式上線、全員 Google 登入、外部 Storage 可用性與所有實機均另列未證明項目，不能把隔離測試當作正式完成。

每次更新都必跑

容量及保存測試不是僅此一版的手動工作；PR 互動 gate 與 protected production candidate 都強制執行，包含 frontend_compat。舊缺陷修正不能透過移除測試、放寬權限、抬高逾時或忽略未知結果取得表面通過。

成效統計口徑

應區分操作數、重試數、失敗事件數及最終成功數。依來源 SHA、操作識別、階段及結果去重，才可算送件失敗率、逾時率及恢復成功率。沒有完整分母時，只報事件數；不能把同批 12 次重試稱作 12 個獨立事故，也不能把讀取變慢稱作資料遺失。
